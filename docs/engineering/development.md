Repositories are registered in `bootstrap.dart`; routes in `core/router/app_router.dart`. Legacy redirects: `/login` → onboarding login, `/role-selection` → owner carousel. Shared API models (e.g. `BabySummary`) live under `apps/mobile/lib/core/domain/`. **Selected baby:** `HomeRepository.resolveSelectedBaby(SelectedBabyStore)` — use for baby-scoped loads (not raw `selectedBabyId` alone). The baby list comes from one shared `BabyListCache` (`core/data/`): fresh for 2 min, concurrent reads share one request (`SingleFlight`), a selected id missing from a cached list triggers one refetch, and the last list is the offline fallback. Repositories that change memberships invalidate it in the data layer (create/edit baby, invite accept, leave, remove member, `membership_ended`); pull-to-refresh marks it stale; `SessionCleanup` clears it and every other user-scoped cache (account, unread count, gallery windows/details, calendar) on sign-out. The shell owns the top-bar state (`ShellChromeSync`: selected baby title + shared `NotificationsRepository.unread`), so tabs never refetch it. Independent requests run in parallel (`waitBoth` / `waitAll3`); small actions (like, vote) are optimistic via `runOptimisticMutation` and revert with a localized message; photo detail reads the id window from `GalleryRepository` and prefetches neighbours. tab screens use `BabyContextReload` (`HomeRefreshSignal.babyContext`, reconnect) and stale-while-revalidate loads via `TabLoadGenerationCache`; **Home** also listens to `HomeRefreshSignal.homeTab` (nav re-tap, cross-tab teasers). `notifyBabyContextChanged` is the single reload signal for baby switch (not `SelectedBabyStore` listeners). `AsyncTabBody` for load errors. **Route-scoped baby:** `HomeRepository.babyById(id)` for deep links and screens keyed by `babyId` in the URL. Static catalogs: `assets/calendar/event_suggestions.json`, `assets/registry/registry_suggestions.json`.

### API layout (`services/api/src/lanonna_api/`)

| Layer | Role |
|-------|------|
| `routers/` | HTTP handlers (`photos`, `events`, `registry`, `fun`, `babies`, …) |
| `domain/` | Membership, permissions, activity + notify hooks (`gallery`, `calendar`, `registry`, `fun`, `home`, `notifications`, `invitations`, **`member_lifecycle`**, `onboarding`, `membership`, `name_suggestions`, `url_validation`, **`users_display`**) |
| `repositories/` | Parameterized SQL only |

**Liveness:** `GET /health` is public (no JWT / App Check) — see route table below.

**CORS:** Mobile clients do not need CORS. For a future browser client, set API env `CORS_ALLOW_ORIGINS` to a comma-separated allowlist (empty = middleware off).

**Member display names (#7):** Family-visible labels come from `app_users.display_name` only. Use [`domain/users_display.py`](../../services/api/src/lanonna_api/domain/users_display.py) (`author_display_name_from_row`, `uploader_display_name_from_row`, `purchaser_display_name_from_row`, `rsvp_display_name_from_row`) — never derive labels from email. SQL should alias `NULLIF(TRIM(u.display_name), '')` as the matching `*_display_name` (RSVP rows use unaliased `display_name` read by `rsvp_display_name_from_row`). The API never invents a name: an empty name comes back as `null` (members, activity actor/target, inbox actor, comment authors, new followers, invite preview inviter) and the app shows `personNameFallback` (“Family member”) via `personDisplayName`. The worker does the same for push copy (neutral “Someone”) and never falls back to an email local part.

**Server request cost (shared layers):**

| Module | Rule |
|--------|------|
| [`db.py`](../../services/api/src/lanonna_api/db.py) | One `psycopg_pool` pool per instance, opened and closed by the FastAPI lifespan. Every repository uses `get_connection()` (commit on success, rollback on error). Size: `DB_POOL_MAX_SIZE` 5 for the API and 2 for the worker, so at most 10 API instances and 5 worker instances use 60 of Cloud SQL's 100 connections. Raise max instances or pool size only together. |
| `read_scope()` in `db.py` | A read-only aggregate (home summary, photo detail, gallery, names, predictions, event detail, `/me/account`) wraps its repository calls in `with read_scope():` so they share one pooled connection in one read-only transaction. Sign URLs after the scope ends, so a connection is never held during IAM calls. A write inside the scope fails. |
| [`storage.py`](../../services/api/src/lanonna_api/storage.py) | V4 signed PUT (upload) and GET (thumb/display read) through one process-wide `GcsUrlSigner`: one credentials object, one storage client, one keep-alive session to IAM `signBlob`. Read URLs last 900 s and are reused per object for at most 300 s (every URL a client gets has at least 10 minutes left); a page's cache misses are signed in parallel. Upload URLs are never cached. Sign many objects with `mint_signed_read_urls` or the batch helpers in `domain/media_urls.py` / `avatar_urls.py`, never one at a time in a loop. |
| `main.py` | `GZipMiddleware` compresses responses of 1 KB or more when the client sends `Accept-Encoding: gzip` (Dart `HttpClient` does by default). |

## Mobile app

```bash
cd apps/mobile
flutter pub get
flutter run --dart-define-from-file=flavors/dev.json

Release and profile builds must pass a non-empty `API_BASE_URL` (see `flavors/*.json`). `AppConfig` reads it with const `String.fromEnvironment`, which honors `--dart-define-from-file=flavors/dev.json`. A missing or empty value fails compilation with `Release builds must set API_BASE_URL via --dart-define-from-file=flavors/dev.json` (L-07). The failure is a const integer-division error, not an `assert`: release and profile compilation strips asserts, which would otherwise fall through to the baked-in dev URL. Debug builds without the define use that dev URL. Do not gate this with a non-const `bool.hasEnvironment` check: AOT release builds report that as false and used to throw on the splash screen.
```

`google-services.json` / `GoogleService-Info.plist` are local (gitignored). Dev flavor: `apps/mobile/flavors/dev.json`. iOS: minimum **15.0**, run `cd ios && pod install` once.

**Android release:** `release` builds enable R8 + resource shrinking (`android/app/build.gradle.kts`, `proguard-rules.pro`). Smoke with `flutter build apk --release --dart-define-from-file=flavors/dev.json` after Gradle changes.

**Android orientation:** the main activity sets `android:screenOrientation="portrait"`, and `main()` calls `SystemChrome.setPreferredOrientations` with `portraitUp` on Android only. iOS orientations are unchanged.

**UI conventions:** Use [`AppColors`](../../apps/mobile/lib/core/theme/app_colors.dart) in feature code (no raw `Color(0x…)`). User-visible copy belongs in [`app_en.arb`](../../apps/mobile/lib/l10n/app_en.arb). API mutations from screens should use [`runMutation`](../../apps/mobile/lib/core/api/run_mutation.dart) unless validation errors stay inline on the form.

### Text input capitalization

User-facing text fields should use [`AppTextField`](../../apps/mobile/lib/core/widgets/app_text_field.dart) (or [`OnboardingTextField`](../../apps/mobile/lib/features/onboarding/presentation/widgets/onboarding_fields.dart) with `AppTextInputKind`) instead of raw `TextField` + `TextCapitalization`. Policy lives in [`app_text_input_kind.dart`](../../apps/mobile/lib/core/input/app_text_input_kind.dart): `personName` (capitalize the first letter of each word or hyphen/apostrophe-separated part; preserve internal capitals such as McKenzie or `QAOwnerName`), `prose` (sentence-case), `none` (email, password, URLs, search). On submit, call `AppTextInputPolicy.normalizeForSubmit(kind, text)` before persisting to the API. Registry shipping street, apt, and city use `personName`; state/province uses the same while typing and [`formatRegistryShippingRegion`](../../apps/mobile/lib/features/registry/domain/registry_shipping_input.dart) on save (uppercase 1–3 letter all-alpha codes). Fun name dedup on the API is case-insensitive per baby and gender.

Transient feedback uses [`AppSnackBar`](../../apps/mobile/lib/core/widgets/app_snackbar.dart): `showInfo` (1s acknowledgments) and `showAlert` (4s validation/errors). Do not call `ScaffoldMessenger.showSnackBar` directly.

### Automated tests

| Layer | Command | Notes |
|-------|---------|--------|
| Mobile unit/widget | `cd apps/mobile && flutter test` | Part of `verify-dev-prerequisites.sh` |
| Mobile chip policy | `cd apps/mobile && bash scripts/check-no-material-chips.sh` | Fails on Material `Chip` / `FilterChip` in `lib/`; runs in `verify-dev-prerequisites.sh` |
| Mobile l10n guard | `cd apps/mobile && dart run tool/check_hardcoded_user_strings.dart .` (or `bash scripts/check-no-hardcoded-user-strings.sh`) | Sink-agnostic AST check (`package:analyzer`) over every `lib/` file except `lib/l10n/` and generated sources. Any string literal that reads as prose (has letters plus a space between words, or starts with an uppercase letter; interpolations and adjacent literals are read from the AST) is a violation wherever it flows — widget args, return values, ternaries, switch arms, exceptions. Ignored only in contexts users never see: directives, annotations, map/index keys, comparisons and case patterns, logging, keys, URIs, regexes, programmer-error/diagnostic throws, `toString()`; lowercase single tokens (`'pending'`, `'image/jpeg'`) are API/format identifiers. Exceptions live in `tool/hardcoded_user_strings_allowlist.txt` as `path\|exact literal\|justification` — the justification is mandatory and must say why the value is not user copy (e.g. stored `relationship_label` values shown via `RelationshipPreset.label`). Self-test: `test/check_hardcoded_user_strings_tool_test.dart`. Runs in GitHub Actions CI |
| Mobile integration | `flutter test integration_test/home_summary_load_test.dart` (device/emulator) | Run locally before release |
| Maestro (Android) | `./maestro/scripts/run-maestro-smoke.sh` after proxy + deploy | See [maestro/README.md](../../apps/mobile/maestro/README.md) |
| API | `PYTHONPATH=services/api/src services/api/.venv/bin/pytest -q services/api/tests` | Run when touching API; included in `verify-dev-prerequisites.sh` compile path — run pytest explicitly for API changes |
| Worker | `cd services/worker && PYTHONPATH=src ../api/.venv/bin/python -m pytest -q tests` | Reuses the API venv (it has the worker's test deps); run when touching the worker |

Run **all three suites** before shipping. Pull requests and pushes to `main` also run [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml): **api** (Python 3.12, the shared `packages/lanonna_activity_copy/tests`, then `pytest` including `tests/integration/` against a Postgres 16 service), **worker** (`pytest` including `services/worker/tests/integration/` against the same Postgres 16 service), and **mobile** (Flutter **3.38.9** pinned: `check-no-material-chips.sh`, the l10n guard, `flutter analyze --no-fatal-infos` — warnings and errors fail, infos do not — and `flutter test --exclude-tags golden`). Pixel goldens are tagged `golden` (`apps/mobile/dart_test.yaml`) because they are rendered on macOS; run them locally on a Mac. Encoder benchmarks are tagged `benchmark`; CI runs them (they assert before/after ratios, not absolute times), and `flutter test --tags benchmark` prints the numbers. Merge only with CI green. Flutter widgets that render the shell top bar (home, gallery, calendar tabs) need `ConnectivityService.forTesting()` and `FakeNotificationsRepository` (`apps/mobile/test/support/`) in the test `MultiProvider`. API repository SQL is mocked in most tests. `services/api/tests/integration/` (pytest marker `integration`) runs search, user provisioning, and the owner-onboarding gate against local Postgres: the fixture applies `infra/db/migrations/` to database `lanonna_pytest` on `127.0.0.1:5432` as user `postgres` / password `postgres` (the worker suite uses `lanonna_worker_pytest` the same way, for notification delivery: recipient prefs/tokens, digest token aggregation, stale-token pruning). Start Postgres with `docker compose -f docker-compose.test.yml up -d` (or any local instance on **5432**), then `PYTHONPATH=services/api/src pytest -q services/api/tests`. Column-conformance unit tests such as `services/api/tests/test_search_repository.py` still lock SQL text. Search `ILIKE` uses a one-character backslash escape: the Python string must be `ESCAPE '\\'`. `ESCAPE '\'` compiles to an empty escape, so `%` and `_` stay wildcards (#3).

**Offset pagination envelope** — collection list endpoints return `{ "items": [...], "offset", "limit", "has_more" }` from `lanonna_api.pagination` with `limit`/`offset` query params. Babies, members, invitations, registry items, photos and notifications default to `limit=50` (max `100`); activity events default to `20` (max `50`); past events (`past=true`) default to `PAST_EVENTS_PAGE_SIZE` (30, max `100`). Calendar month/upcoming views return the same envelope in one page, bounded by `LIST_EVENTS_MAX_ROWS` (500); `has_more` signals the cap. No app-facing list endpoint returns a bare JSON array (the internal admin announcements list is not used by the app). Mobile parses via `lib/core/api/offset_page.dart` (`parseOffsetPage`, `maxOffsetPageLimit`); collections the UI needs whole (babies, members, invitations, registry) use `fetchAllOffsetPages`. Scrolling lists refresh after a mutation with `refreshPaginatedWindow` (`core/domain/paginated_list_refresh.dart`), which merges new head rows or re-fetches the loaded window without dropping rows the user already scrolled to. Repositories page in SQL (`repositories/_paging.py`) with a stable `ORDER BY` tiebreak, and routers fetch `limit + 1` rows for `has_more`.

**Signed read URLs** expire after **900s** ([`storage.py`](../../services/api/src/lanonna_api/storage.py)); the API may serve the same URL for one object for up to 5 minutes, so a URL always has at least 10 minutes left when it arrives. `CachedSignedImage` accepts optional `onSignedUrlError` (one callback per widget mount) so parents can refresh API data (home teasers, photo detail).

**Images (one policy, `core/media/`):** every network image renders through `CachedSignedImage` (photos, thumbnails, covers, keepsake, avatars; never `Image.network`), and a picked local photo through `LocalPhotoImage`.
- **Cache key:** `imageCacheKeyForUrl` keys a signed GCS URL by host + object path (the object never changes; the signature does), so callers pass no keys and one object is cached once wherever it shows. The disk cache is `flutter_cache_manager`'s default store, cleared on sign-out (`evictSignedImageCaches`).
- **Decode size:** `DisplaySizedImage` decodes at the slot's size × device pixel ratio for its `BoxFit` (cover: larger scale; contain: smaller), never upscales and keeps the aspect ratio. `CachedSignedImage` measures its slot; precache with `precacheSignedImage(…, logicalSize:)` at the slot size so the screen reuses that entry.
- `CachedSignedImage` keeps `CachedNetworkImage`'s look (sage-tint placeholder, 500 ms fade-in); `placeholder`, `error` and the fade durations are overridable (the avatar shows its ring, no fade, initials on error).

**Lists:** an unbounded or paged collection inside a scroll view is a sliver (`SliverList` / `SliverGrid` builders in the screen's `CustomScrollView`, e.g. `GalleryPhotoGrid`), never a `shrinkWrap` list, so only visible rows are built. `shrinkWrap` stays fine for small fixed sets (month grids, short sheet lists).

**Fonts are bundled, never downloaded:** [`app_fonts.dart`](../../apps/mobile/lib/core/theme/app_fonts.dart) lists every variant the theme uses (Baloo 2 700/800, Inter 400/500/600/700, Dancing Script 700); their files live in `assets/google_fonts/` as `<Family>-<Weight>.ttf` (the exact files `google_fonts` would fetch), with OFL licenses registered for the licenses page. `main()` turns off `GoogleFonts.config.allowRuntimeFetching` and preloads the variants before `runApp`, so the first frame is already in the brand fonts (and the app works offline on first launch). A new weight means adding its file and its entry in `AppFonts.bundledVariants`; `test/app_fonts_test.dart` fails if the theme uses a variant that is not bundled.

**Avatars:** every initials avatar (`AccountTintedAvatar`, `AvatarStack`) renders its fallback through [`AvatarInitials`](../../apps/mobile/lib/core/widgets/avatar_initials.dart) and the one rule in [`display_initials.dart`](../../apps/mobile/lib/core/presentation/display_initials.dart): display name, else the email, else a neutral person glyph (never a placeholder word). The signed-in user's avatar reads `AccountRepository.identity`: the loaded profile, else the last one this user loaded on the device ([`AccountIdentityStore`](../../apps/mobile/lib/features/account/data/account_identity_store.dart), uid-scoped, cleared on sign-out), so it stays right offline.

**Shell vs subpage chrome (FR-SHELL-001):** Bottom-tab screens wrap content in `ShellTabLayout` (home top bar: leading **add baby** (`+` → `/baby/create`) and **invite** (`group_add_outlined` → `/invite-family` when the user has an owner baby; otherwise a dialog → add baby), centered baby switcher, notifications bell, account avatar). Drill-downs, settings/account stack routes, and forms such as calendar/registry edit use `PrototypeSubpageScaffold` (back + centered title only). **Detail drill-downs render on the root navigator** (`parentNavigatorKey: appRootNavigatorKey`: photo detail, event detail and event edit keep their `/gallery/…` and `/calendar/…` paths), so they can be pushed from a tab, Home, the Inbox, the activity feed or a push tap, and Back returns to the opener. [`navigateAppDeepLink`](../../apps/mobile/lib/core/router/deep_link_navigation.dart) reads the route tree (`tabBranchForLocation`): tab pages switch tab (`go`), every other target is pushed. Leaving a detail after delete / not found uses `popOrGo(context, <tab root>)` ([`subpage_navigation.dart`](../../apps/mobile/lib/core/router/subpage_navigation.dart)). Do not stack `shellHomeTopBar` on subpages. Icon-only controls use [`AppIconButton`](../../apps/mobile/lib/core/widgets/app_icon_button.dart), which requires a label (tooltip + semantics) and hides the icon glyph from the screen reader. Subpage Back, calendar month arrows, home photo thumbnails (`Open photo`), and tappable activity rows (the activity summary) follow that pattern (#49).

**Home scroll sections:** Build blocks with [`HomeScrollSection`](../../apps/mobile/lib/features/home/presentation/widgets/home_scroll_section.dart) (header + body + `sectionBlockSpacing`). Trailing controls: [`HomeSectionLink`](../../apps/mobile/lib/features/home/presentation/widgets/home_section_trailing.dart) / `HomeSectionMeta` only — not raw `TextButton` on section headers. Bordered bodies: `HomeScrollSection.bordered` → `AppBorderedSurface` + `AppMetrics.surfacePadding` (or `padding: EdgeInsets.zero` for `ListTile` lists). Low-level [`HomeSectionHeader`](../../apps/mobile/lib/features/home/presentation/widgets/home_section_header.dart) uses fixed `sectionHeaderRowHeight` + `sectionTitleGap`.

**Event times (UTC-in / local-out, #4 / #68):** API `starts_at` / `ends_at` are UTC instants. Calendar **Today** lists every event whose **local start date** is today (including starts earlier the same day); data comes from the **current** local `month=YYYY-MM` list, sent as `starts_from` / `starts_before`: the UTC instants of local midnight on the 1st and on the 1st of the next month ([`calendarLocalMonthQueryParams`](../../apps/mobile/lib/features/calendar/domain/calendar_event_lists.dart)), so bounds match the device calendar even when a DST change falls inside the month. **Upcoming** uses `GET …/events?upcoming=true` (`starts_at >= now`) and drops rows already shown under Today — see [`partitionCalendarListEvents`](../../apps/mobile/lib/features/calendar/domain/calendar_event_lists.dart) and [`CalendarTodayUpcomingSections`](../../apps/mobile/lib/features/calendar/presentation/widgets/calendar_today_upcoming_sections.dart). Home teasers still use home-summary `upcoming_events` only. Create and update reject an `ends_at` earlier than `starts_at` with **400** via [`validate_event_time_range`](../../services/api/src/lanonna_api/domain/date_validation.py). A missing or explicit null `ends_at` is an open-ended event. An end equal to the start is allowed. Naive datetimes are treated as UTC. Parse with [`parseApiInstant`](../../apps/mobile/lib/core/time/app_date_time.dart) at model boundaries (`CalendarEvent`, home `NextUpEvent`). Submit with `toApiInstant`. Display via `formatEventListDateTime`, `formatEventDetailWhen`, and home badge helpers — do not format raw `DateTime` fields in widgets. Announcement birth time stays `HH:MM` on the API and is shown with `formatApiClockTime` (`DateFormat.jm`, so `15:30` is `3:30 PM` in en-US). Calendar month/day math uses `eventLocalStart` / `eventOnLocalCalendarDay` (re-exported from `calendar_display.dart`). **Date-only API strings** (`expected_birth_date`, birthdate guesses, invite preview, profile DOB, announcement birth date): parse with `tryParseApiCalendarDate`; display with `formatApiCalendarDate` / `formatApiCalendarDateFromParts` and `localeNameForFormatting(context)`; submit with `toApiCalendarDate` (#19). Use [`PrototypeDateField`](../../apps/mobile/lib/features/onboarding/presentation/widgets/onboarding_prototype_widgets.dart) for date tiles (event form, create baby) — never hand-format `YYYY-MM-DD` in widgets.

## API rate limiting

Sensitive routes (`POST /v1/photos/init`, `POST …/invitations/batch`) use an **in-process** per-IP sliding window in `middleware/rate_limit.py` (30 requests / 60s per path per instance). Cloud Run scales horizontally, so the **effective** cap is roughly `30 × instance count` until you add a shared limiter (e.g. Cloud Armor, Redis/Memorystore) at the edge. No shared limiter is deployed in v1; document and monitor before wide public beta.

## Firebase JWT audiences

API verifies Firebase ID tokens with `firebase_admin.auth.verify_id_token`, then checks the token `aud` claim against `Settings.firebase_audience_allowlist()` (`GCP_PROJECT_ID` when `FIREBASE_AUDIENCES` is unset). Sideloaded dev APKs and emulators using the same Firebase project are unaffected. Misconfigured `FIREBASE_AUDIENCES` causes 401 for all real clients.

**Invite emails (FR-INV-004 / FR-INV-007 / #39 / #62):** batch create publishes `{"type":"send_invite_email",…}` to **`lanonna-async-commands`**; the batch is set-based: one query loads existing members and pending invites for every row (`load_invite_targets`), resends and new rows are written in one transaction (`write_batch_invitations`, `ON CONFLICT … DO NOTHING` on the one-pending-invite-per-email index so a concurrent duplicate becomes `skipped_duplicate`), and emails are queued after commit. Owners can **`POST …/invitations/{id}/resend`** from Manage followers. The worker records `email_delivery_status`, `email_last_error` (diagnostics only; the app shows the localized delivery status, not this text), and `email_send_attempts` (migration `034`); transient Mailjet/network errors return `InviteSendOutcome.RETRY` → HTTP **500** so Pub/Sub backoff retries (no in-process `sleep` retries inside the push request), permanent failures ack **204** with `email_delivery_status = failed`. **In-app + push notifications:** API `domain/notifications.py` publishes `notify_fan_out` or `notify_user` to **`lanonna-async-commands`**; the worker handles the same types on `POST /pubsub/push` and inserts `notifications` rows. **Instant FCM** only when `push_notifications_enabled` and `notification_digest=realtime`. **`daily`** digest: in-app inbox only (no batch push). **`weekly`** digest: one summary push (Sunday 14:00 UTC) via Cloud Scheduler → Pub/Sub `{"type":"weekly_notification_digest"}` on **`lanonna-async-commands`** (`./scripts/setup-weekly-digest-scheduler.sh`; optional manual `POST /cron/weekly-notification-digest` on worker).

**Structured notifications and activity (migrations `036` / `037` / `038` / `039`):** the API never writes user-facing copy. Every publish carries a `kind` (`NotificationKind` in [`packages/lanonna_activity_copy`](../../packages/lanonna_activity_copy/): `photo_shared`, `photo_squished`, `photo_commented`, `event_created`, `event_rsvp`, `event_commented`, `registry_purchased`, `registry_buying`, `invite_accepted`, `baby_arrived`), display `params` (`event_title`, `item_name`, `rsvp_status`, `baby_name` — present only when the baby has a name, via `baby_name_params` —, …) and `actor_firebase_uid` (`FanOutSpec` / `NotifyUserSpec` in `domain/notifications.py`). The worker rejects (acks) a notify payload without a known kind, derives `notification_type` (icon category) from the kind, stores `notification_kind` + `params` and snapshots `actor_display_name` in the inbox `INSERT`, and renders the **push** text with `push_copy` — the OS shows FCM `notification` payloads without running app code, so push copy is the one place English text is built server-side (adding a locale means storing the user's locale and choosing copy per recipient there). The app renders inbox rows from ARB by kind (`inboxSentence`) and activity rows by `event_type` + `params` (`activitySentence`), bolding names through `PlaceholderRichText`; stored `title` / `body` / `summary` are shown only for unknown kinds/types or legacy rows missing a value. Activity rows (`insert_activity_event`) store `params`; names are resolved at read time (`target_display_name` comes from `payload.target_firebase_uid`). Migration `038` backfilled legacy rows from structured sources only (deep links, referenced rows, the fixed titles/summaries the API always wrote); RSVP and registry inbox rows keep a `NULL` kind. **Unread state:** `NotificationsRepository` is a `ChangeNotifier` (same pattern as `GalleryRepository` / `CalendarRepository`); mark-read, mark-all-read (`POST /v1/me/notifications/read-all`) and FCM foreground receipt call `notifyInboxMayHaveChanged()`, and the shell bell listens to it.

API local dev: `NOTIFY_PUBLISH_DISABLED=true`. Mobile: `firebase_messaging`, `PushNotificationService` → `PUT`/`DELETE /v1/me/device-tokens` on auth; opens FCM `data.deep_link` (and optional `data.baby_profile_id`) via `navigateAppDeepLink` in `core/router/deep_link_navigation.dart`. **Shell vs root:** tab destinations (`/gallery/photo/:id`, `/calendar/event/:id`, `/registry`, …) must use `GoRouter.go` so the indexed shell is not stacked twice; inbox/profile/settings use `push` on the root navigator. Inbox rows include `baby_profile_id` when present so multi-baby accounts load the right context before navigation. Worker SA: `roles/firebasecloudmessaging.admin` on dev if sends fail.

## Database

Apply every SQL file in `infra/db/migrations/` in lexicographic order (the [migrations README](../../infra/db/migrations/README.md) lists them all and is the single source for the current set). Cloud SQL Auth Proxy may use port **5432** or **5433** — set `DB_PORT` consistently (`apply_migrations.py` defaults to **5432**; Maestro, `clear_dev_test_data.py`, and `verify-dev-migrations.sh` default to **5433**). Cloud SQL via Auth Proxy + `infra/db/apply_migrations.py` or `psql -f` per file. Use the venv under `infra/db/.venv` (`pip install psycopg`) or any environment with `psycopg` installed.

| Script | Purpose |
|--------|---------|
| `apply_migrations.py` | Runs every `migrations/*.sql` in lexicographic order (DDL is idempotent; safe to re-run on dev) |
| `clear_dev_test_data.py` | Delete baby-domain rows for a test user; optional `--reset-onboarding` |
| `scripts/hard_delete_user.sh` | One-liner hard delete by email (SQL + GCS + Firebase); uses `infra/db/.venv` |

Set `DB_HOST`, `DB_PORT` (e.g. `5433` if 5432 is in use), `DB_PASSWORD`, and `DB_USER` / `DB_NAME` as needed (defaults match dev Cloud SQL via proxy).

## Performance

How to measure performance, what is already optimized, and a prioritized backlog. Manual encode/cache checks: [pre-beta-qa.md](pre-beta-qa.md). Offline expectations: [requirements.md](../product/requirements.md) (NFR-OFFLINE-001, FR-GAL-002).

### Goals

- Fast tab switches; gallery thumbs from disk cache; responsive home after baby switch (`HomeRepository.resolveSelectedBaby`).
- Paginated API reads, thumb-first feeds, FCM instead of polling ([platform-architecture.md](platform-architecture.md) principles 3–4 and 9).

### How to measure

| Layer | Tool | Watch |
|-------|------|--------|
| Flutter | DevTools; `flutter run --profile` | Gallery jank; home rebuild scope |
| API | Cloud Run latency/5xx; request ID logs | p95 on `home-summary`, gallery list, `photos/init` |
| DB | Query Insights; `EXPLAIN` | Scans on `activity_events`, `photos` |
| GCS | Billing egress | Thumb vs display read ratio |

Baseline on **profile/release** build (`flavors/dev.json`): cold start → home → scroll gallery → calendar month change.

### Already optimized

| Area | Implementation |
|------|----------------|
| Cold start | [`AppVersionGate`](../../apps/mobile/lib/core/version/app_version_gate.dart) checks `/v1/app/version` in the background (5s timeout); onboarding carousel shows without waiting. Signed-in [`AppSession.refreshFromApi`](../../apps/mobile/lib/features/onboarding/presentation/app_session.dart) runs after first frame ([`LaNonnaApp`](../../apps/mobile/lib/app.dart)); router uses cached onboarding status until fresh. [`BiometricAppLock`](../../apps/mobile/lib/core/auth/biometric_app_lock.dart) waits for GoRouter before applying lock routes. Start-up runs Firebase, then App Check activation together with local bootstrap (storage, connectivity, cold-start link) in [`main.dart`](../../apps/mobile/lib/main.dart). App Check: [`startFirebaseAppCheck`](../../apps/mobile/lib/core/app_check/app_check_bootstrap.dart) returns an [`AppCheckTokenSource`](../../apps/mobile/lib/core/app_check/app_check_token_source.dart): one in-flight SDK `getToken` (the SDK caches and auto-refreshes), bounded at 10 s, started at launch when a user is signed in; `ApiClient` reads it alongside the ID token. Debug token logging retries in the background. Home requests the summary for the persisted selected baby together with the baby list (`fetchHomeSummary(speculative: true)`, which never shows the membership-ended notice), then uses it only if that baby is still selected. Android launch screen: brand background `#F6F6F7` and the La Nonna wordmark (`res/drawable*/launch_wordmark.png`, generated by `tool/render_launch_wordmark.py`; Android 12+ via `values-v31` `windowSplashScreen*`). |
| Tab refresh | Split `HomeRefreshSignal` (`homeTab` vs `babyContext`); SWR shell tab loads (`TabLoadGenerationCache`); gallery `GalleryRepository` notify runs `refreshLoadedPhotoList` (`features/gallery/domain/gallery_loaded_pages.dart`, a thin wrapper over the generic `refreshPaginatedWindow`) — fetches the head page once and merges new rows instead of capping at the previous loaded count; photo detail opens on `fetchPhoto`, then pages swipe ids in the grid's sort (`GalleryRoutes.photoDetail(id, sort:)` passes `?sort=`). Home keeps the last good summary per baby across baby switches (offline fallback); it is cleared on sign-out |
| Upload | `display_encode.dart`: one lossy WebP encode (q80, method 2) off the UI isolate, 2048 px display / 512 px avatar, re-encode only when over the 2 MB cap (`storage.py`). A 2048 px photo encodes in ~0.3 s instead of ~9 s (`flutter test --tags benchmark test/display_encode_benchmark_test.dart` prints before/after) |
| Feed/detail | Worker thumbs; signed read URLs (900s TTL) from one shared signer with a per-object 5-minute reuse cache and parallel signing; `CachedSignedImage` + optional `onSignedUrlError`, disk-cached by object path and decoded at slot size (a 2048x1536 photo in the 1080 px detail square decodes to 1440x1080, 6.2 MB instead of 12.6 MB); the gallery grid is a lazy `SliverGrid` (first open fetches the ~20 visible thumbnails, not all 46+) |
| Rendering | Brand fonts bundled and preloaded before the first frame (`AppFonts`); no fallback-font swap on first launch |
| Server cost | Pooled DB connections opened at startup; aggregates (`home-summary`, photo detail, gallery, names) run bounded queries on one connection via `read_scope()` (home: 17 queries on 17 connections → 9 on 1); gzip for responses ≥ 1 KB; `resolve_app_user` reads first and writes only when something changed |
| Pagination | One SQL-paged `{items, offset, limit, has_more}` envelope on every list route (incl. past events); capped `home-summary` teasers; per-row aggregates folded into list queries (`active_owner_count`, digest unread counts, bulk photo tags) |
| Notify | `safe_enqueue_fan_out` after DB commit |
| Rate limits | Photo init + invite batch (`rate_limit.py`) — per-instance; see [open-gaps.md](open-gaps.md) M-09 |
